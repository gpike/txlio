# WO-0001: Local Supabase Dev Stack

## Objective
Create a Docker-backed local Supabase instance for Txlio development, apply migrations and seed data, and provide scripts to run local app development against the local stack.

## Scope
- Supabase local stack configuration under `supabase/`
- SQL migration(s) under `supabase/migrations/`
- Seed script under `supabase/seed.sql`
- NPM scripts and shell runner for local development
- Documentation updates for usage

## Deliverables
- [ ] `supabase/config.toml`
- [ ] `supabase/migrations/*_init.sql`
- [ ] `supabase/seed.sql`
- [ ] `scripts/dev-local.sh`
- [ ] `package.json` scripts for local stack lifecycle
- [ ] `.env.example` notes for local and hosted Supabase

## Runbook
- Start local Supabase only: `npm run local:supabase:start`
- Reset local DB (migrations + seed): `npm run local:supabase:reset`
- Start app against local Supabase without reset: `npm run dev:local`
- Start app with forced reset: `npm run dev:local:reset`

## Acceptance Criteria
- `npm run local:supabase:start` starts local Supabase (Docker)
- `npm run local:supabase:reset` applies migrations + seed to local DB
- `npm run dev:local` starts Next.js with local Supabase env injected
- Local stack can be stopped via `npm run local:supabase:stop`
- Team can follow docs with no hidden manual steps

## Notes
- Uses Supabase CLI (which orchestrates Docker containers).
- Local secrets are generated by Supabase and injected at runtime by script.
- Local stack is isolated with project-specific config and dedicated Docker network: `txlio-supabase-net`.
- Startup excludes non-essential analytics/vector services to avoid port collisions with other local Supabase projects.
